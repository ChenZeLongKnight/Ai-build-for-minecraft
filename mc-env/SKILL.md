# Minecraft AI 建筑环境配置

本技能是整个技能套件的入口。新环境中第一次使用时，先完整执行一遍本流程，向用户输出体检报告；全部通过后，告知用户可以开始使用 mc-design、mc-build、mc-modify。

## 基本原则

1. 能自动完成的绝不询问用户。整个流程中最多向用户提出一个问题，即引擎目录的位置。
2. 检查按顺序执行，前一项未通过时记录问题并继续检查其余项，最后统一汇报，不要查一项停一项。
3. 报告必须逐项给出结论，格式为通过、缺失但不影响主流程、缺失且需要处理三种，缺失项附带具体的解决办法。

## 检查清单

按以下顺序逐项检查。

### 第一项，Node.js

执行 `node --version`，版本不低于 20.10.0 即通过。版本过低或不存在时，请用户安装 Node.js LTS 版本后重试。

### 第二项，Minecraft 游戏

询问用户游戏是否已经启动、世界是否已对局域网开放并允许作弊。同时检查 25565 端口是否有服务在监听。游戏未启动时提醒用户先完成这两步，此项不通过不阻塞其余检查。

### 第三项，蓝图引擎

确定引擎目录，规则如下。优先读取环境变量 `MC_BUILD_HOME`；未设置时检查默认目录 `D:/mcserver` 是否存在且含有 `schematics` 子目录与 `dist` 目录；两者都不可用时，向用户询问引擎安装位置，这是全流程唯一一次询问。引擎目录确定后，若 `schematics` 子目录不存在则自动创建。随后检查引擎完整性：`dist/main.js` 与 `dist/tools/schematic-tools.js` 存在、`node_modules` 中能找到 `prismarine-nbt`。引擎尚未克隆构建时，给出克隆与构建的具体命令，见仓库 minecraft-mcp-server-blueprint 的说明。

### 第四项，MCP 连接

在当前会话可用的 MCP 工具列表中查找 `build-blueprint`、`verify-region`、`list-schematics` 三个工具。能找到即通过；找不到时，说明客户端尚未配置 minecraft 服务器或未重新加载，给出配置方法：在客户端的 MCP 配置中加入本引擎，命令为 node，参数为引擎目录下 `dist/main.js` 加上 `--host localhost --port 25565 --username <角色名>`，配置后需要重新加载客户端。

### 第五项，浏览器自动化

检查会话中是否有浏览器自动化工具可用，例如 browser-use 提供的工具。缺失时说明网页体素设计器无法使用，给出安装 browser-use 的指引。此项缺失不影响建造与修改，只影响自主设计路线。

### 第六项，图片还原依赖

此项为可选项，仅在使用照片转建筑功能时需要。检查 Python 版本不低于 3.10，以及 numpy、Pillow、scipy、onnxruntime 四个包是否已安装，再检查模型权重目录 `~/.workbuddy/models` 或环境变量 `SUBJECT_MODEL_DIR` 指向的目录中是否存在可用的 onnx 权重文件。任何一项缺失时标记为缺失但不影响主流程，并给出安装方法，权重获取方式见技能套件 models 目录下的说明。

## 收尾

全部检查完成后，向用户输出一份体检报告，逐项列出结论与待办。报告之后写明一句话结论：环境就绪，可以直接对 agent 说设计蓝图、建造、修改来使用完整流程；或环境尚有缺失，按报告中的办法补齐后重新运行本技能。
