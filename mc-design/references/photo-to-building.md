# 照片 → MC 建筑：路线选择

用户丢一张照片说「照这个建」，先判断**照片类型**，再选路线。照片类型决定上限，算法只是次要因素。

## 四条路线的适用面

| 照片是什么 | 方法 | 保真度 | 工作量 |
|---|---|---|---|
| 像素图 / 拼豆 / 马赛克图 | 网格采样（见 `photo-to-pixelart.md`） | 几乎 1:1 | 低 |
| 正交立面图 / 三视图 | 剪影求交（visual hull） | 高 | 中 |
| 普通透视照片，但建筑有名 | 搜图纸 / 搜现成 schematic | 最高 | 最低 |
| 普通透视照片，建筑无名 | SfM 摄影测量 → 点云 → 体素化 | 低（噪声大） | 很高 |

**结论先说**：真正值得做的只有前三条。第四条听着酷，实际产出是「能看但很丑」的噪声体块，除非只是要个大致轮廓。

## 路线 2：三视图剪影求交（唯一真正实用的 3D 路线）

Minecraft 建筑天然轴对齐、方块化，正是 visual hull 最擅长的情况。原理是：一个方块要同时落在三张剪影的投影里才保留。

```
voxel(x,y,z) 存在  ⟺  正视图(x,y) ∧ 侧视图(z,y) ∧ 俯视图(x,z)
```

得到的是「能同时解释三张图的最小体块」，再拿正视图的颜色给朝前的面着色。

要点：
- 输入必须是**正交投影**（远距离长焦拍的、或截图/图纸），透视照片要先做透视校正，否则剪影边界会系统性偏移。
- 每张图先转成二值剪影 mask（背景色取反 → 最大连通域 → 填洞）。
- 三张图要**统一方块尺度**：各自测出该图上「1 格 = 多少像素」，归一到同一格数。
- 单张立面图也能用：把厚度固定为 1，直接得到浮雕墙，就是已跑通的立像路线。
- 只有两张图（正 + 侧）时效果差很多，缺少俯视约束会让屋顶和出檐一路拉伸到底。

### 拍摄清单（该向用户要什么）

必拍三张：正面、侧面、俯视。每张的硬要求，按重要性排序：

1. **准正交**：站远 + 拉长焦（等效 ≥50mm，手机用 3–5× 变焦档），距离 ≥5 倍建筑高度。广角近拍是头号杀手，剪影边界会随深度系统性偏移。
2. **正对**：相机光轴垂直于立面，不仰拍不俯拍，否则竖直边会收敛。
3. **拍全**：四边留白，不切角。
4. **背景干净**：天空或纯色墙，与主体反差大；避开树木、电线、车辆遮挡。

必须一并索要的两个标定信息（最常被漏掉）：一是**尺度参照**，画面里放一把尺、一张 A4 纸或一扇已知尺寸的门，也可以直接告知「门高 N 米」，用于换算「1 格 = 多少像素」；二是**机位说明**，即每张的拍摄方向以及各张是否同一距离。

光照：阴天或散射光最佳；强侧光的阴影会吃掉轮廓，逆光直接作废。

优先索要的替代品（质量远高于照片）：平面图 / 立面图 / 剖面图（手绘也行，但须翻拍正）、现成的 `.schem` / `.litematic`、他人 MC 作品的正视图截图。

不必索要：精确测量数据、环绕数十张照片（3–4 张足够，再多还需配准反而添乱）、深度图或点云。

只有单张随手拍时，只能做固定厚度的浮雕（见 `photo-to-pixelart.md` 的立像路线），或明确告知用户会退化为噪声体块。

## 路线 4：摄影测量的现实

- 工具链：多图 → COLMAP / Meshroom → 稠密点云 → Poisson 网格 → 体素化 → 清理。
- 或单图：Depth Anything V2 / MiDaS 出深度 → 反投影点云 → TSDF 融合。单图深度是**相对**深度，尺度不确定，做出来的比例不可信。
- 主要问题不是重建本身，而是**转成方块**：点云表面是连续曲面，体素化后层数远超 MC 合理高度；材质无法回推；树木、行人、电线全是孔洞和飞点。
- 结论：只在「只要大概体块、不要细节」时考虑，且必须留出大量人工清理工时。

## 路线 3：别忽略搜图纸

照片是故宫太和殿、比萨斜塔这类知名建筑时，直接搜平面图 / 立面图 / 已有 MC 作品 / 现成 `.schem` / `.litematic`，比从照片重建靠谱一个数量级。这一步应该在动手任何重建之前先做。

## 决策顺序（按此顺序问）

1. 照片本身是像素图吗？是则走网格采样。
2. 不是的话，建筑有名吗？有名则先搜图纸和现成 schematic。
3. 没搜到或建筑无名，能拿到正交视图吗（图纸，或自己远距离长焦拍）？能则走三视图剪影求交。
4. 只有随手拍的透视图，只能做单图浮雕（选一个主立面），或明确告知用户 SfM 路线的产出质量与工时。
