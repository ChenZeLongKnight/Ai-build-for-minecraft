# 图片 → MC 像素立像

三条脚本入口的选用与命令写在 SKILL.md 的「图片还原」一节与「命令速查」中，本文不重复。本文只保留两类脚本无法自行处理的内容：必须由使用者给出的参数，以及自动抠图不理想时的手工退路。

## 运行前提

三个转换脚本都依赖 numpy 与 Pillow，照片脚本另外需要 scipy 与 onnxruntime；若不满足，安装到隔离虚拟环境即可，不要污染系统环境。显著性分割的权重放在 `C:/Users/ASUS/.workbuddy/models/`（路径可用环境变量 `SUBJECT_MODEL_DIR` 覆盖），脚本按体积校验与加载自检自动挑选完好的一个，无需手工指定；权重缺失时脚本会打印下载地址。

## 必须由人给出的两个参数

**平涂像素图的 `--width` 要填原生格数，不能凭观感放大。** 这类源图本身就是格子（网格线加上每格一色），分辨率必须等于原图的格子数，多一格或少一格都会让描边变粗或漏线。定法是把原图放大后数出一格的像素宽（例如格宽约 6.4 像素、图宽 474 像素，得 474÷6.4≈74），再试相邻三档（73／74／75）对比挑选最干净的一档。自动测周期的方法（傅里叶变换、自相关、网格线拟合）在这类低对比网格上都不收敛，不必浪费轮次。

**实拍照片的 `--bg-tol` 必须现场测，默认值只是起点。** 测法是先采样目标区域的中值色，算出它与外圈背景色的 Lab 距离，再取略大于该距离的值。同一张桌面从阴影到高光可以跨越十几到四十多的 Lab 距离，阈值偏低会留下大片阴影背景。

## 自动抠图不理想时的手工退路

这条退路只在源图本身是格子（拼豆成品实拍、马赛克墙面）且自动抠图效果不可接受时使用。实拍照片带透视、光照梯度和 JPEG 噪声，自动测格子周期会全线失效，以下各步都靠人眼判读。

1. **测珠径。** 把原图局部放大五倍以上，人眼数一颗珠子占多少像素。自相关、傅里叶变换、相位集中度在烫平的拼豆照片上都不可靠。
2. **对齐网格相位。** 把候选网格画到原图上（绿色竖线加品红横线）再截图核对，错位半格一眼可见。每个独立元件（每个人物、每块拼豆板）都要单独拟合原点，并把结果写死进脚本。
3. **逐格采样。** 取格心 11×11 区域，算前景像素的中值而不是均值或模式投票，中值对边缘混色最稳；前景占比低于 0.5 的格子判为空。前景掩码的做法是按背景色取反，做开运算，保留最大连通域以自动丢掉镊子、盒子等杂物，再闭运算并填洞。
4. **曝光归一。** 把所有前景格转成 Lab，取 L\* 的 92 分位，用 `s = 96 / p92`（钳在 0.9 到 1.4 之间）统一缩放 L\*。系数必须由所有元件合并后的前景统一求出、统一施加，否则两个人物会得到不同肤色。
5. **Lab 最近邻配色，并补两条特殊规则。** 肤色整片归一（`L>45 且 1.5≤a≤25 且 3≤b≤28` 一律归到同一个方块），否则人脸会被切成杂色斑块；极暗归黑（`L<20` 一律归黑），否则头发上会散布反光灰点。
6. **体素域清理，顺序不可调换。** 灰点去斑（被四个以上黑邻居包围则变黑，但白色要保留，那是眼睛高光）→ 中性色平滑 → 3×3 众数 → 删孤立格 → 最外层强制黑描边。
7. **合成。** 多个元件按底边对齐，中间留 2 到 4 格。坐标映射为 `x = 横向格号`、`y = 底边 - 纵向格号`、`z = 0`，单层薄墙的正反两面观感相同。落地前先用 `get-block-info` 探明基面所在层。

## 浅色人物像的调色板

| 用途 | 方块 |
|---|---|
| 头发 / 描边 / 眼睛 | `black_concrete`、`black_wool` |
| 皮肤 | `white_terracotta` |
| 高光 / 白衣服 | `white_wool`、`white_concrete` |
| 阴影 | `light_gray_concrete`、`gray_concrete` |
| 腮红 / 嘴唇 | `pink_concrete`、`pink_wool` |
| 淡紫衣服 | `purpur_block` |
| 深紫图案 | `amethyst_block` |
| 蓝边 | `light_blue_concrete`、`blue_concrete` |
| 金色点缀 | `orange_concrete`、`yellow_concrete` |

`purpur_block` 偏粉紫，是浅紫布料最接近的原版方块；`amethyst_block` 更饱和更暗，两者搭配正好做「浅紫衣服加深紫图案」的双色层次。

## 何时不必自己提取

上面三条脚本入口针对的是带透视、光照和噪声的实拍输入。若来源本身就是干净位图，或者用户只是想让地图上显示一张图而不打算真实建造，应先考虑现成工具。

- **只在地图物品上显示图片（不产生方块）**：`Image2Map` 是 Fabric 服务端模组，指令为 `/image2map create <图片> <尺寸>`，单张地图 128×128 像素，超出会自动切成多张，前提是安装 Fabric；`ImageOnMap` 是 Paper/Spigot 插件，可在游戏内贴网址生成，适合服务器。纯原版且不愿装模组时，改用下面的网页工具。
- **要真实方块**：用网页工具上传图片，导出 `.litematic` 或 `.schem`，再用 `litematic-convert` 转成 JSON 交给 `build-blueprint`。可用工具有 MapartCraft、Cartographer（调色板已含 1.21.4）、priner.net 的 maparttool（输出原版结构文件，可用 `/place template`），以及 minecraftart.net、Spritecraft 等同类替代。
- **地图画的四条关键限制**：地图基色只有约 61 种，照片直转会糊成色块，上传前应先提对比度和饱和度；把地形做成阶梯（本格高度减去正北邻块高度）可把色板扩到约 180 色，是严肃地图画的标准做法；作品最北边必须多铺一行支撑方块，否则顶行永远偏暗；抗锯齿必须自己处理，抖动算法里 Bayer 的规则摩尔纹最差。一张地图是 128×128 方块，多张可拼接，工程量按平方增长，而本项目的秒落通道在这种尺度上优势极大。
